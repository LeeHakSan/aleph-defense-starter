# 내 ZTNA·XDR 패키지

## 무엇을 누가 만들었나

| 출처 | 들어 있는 것 |
|---|---|
| 학생이 만든 것 | 판정기(`src/decider.mjs`), 탐지 규칙(`src/detect.mjs`), 접속 앱(`public/`), 자료실(`api/`, `src/*.mjs`, `supabase/*.sql`: 내 메모 API, 로그인 토큰 확인, 공지 구역, 한 건 복원, 기기 승인 확인 자리, 탈환 작전실), 점검 코드(`src/attack-check.mjs`, `src/rule-check.mjs`) |
| 제공 엔진 | ALEPH SDP 엔진. 요청마다 학생 판정기를 부르고 결과를 집행하며, 학생 탐지 규칙의 회수 제안 집행과 요청 서명 확인을 맡습니다. 이 저장소에는 엔진 코드가 없습니다. |

제공 엔진: ALEPH SDP 엔진 사용(이 저장소에 없음). 비밀값(서버 전용 키 등)은 이 안내에 넣지 않고 Vercel 비밀 입력란에만 둡니다.

아래는 패키징 단계(4~6차) 양식입니다. 아직 채우지 않은 칸은 완성으로 보지 않습니다.

이 파일은 패키징 단계의 배포 안내 양식입니다. 아직 완성된 제품의 안내서가 아닙니다. 1~12단계에서 실제로 만든 기능에 맞춰 아래 내용을 채운 뒤, 쓰던 프로젝트가 아닌 새 Vercel 프로젝트에서 적힌 순서대로 시험하세요.

## 새 프로젝트에 배포

1. Vercel에서 **새 프로젝트**를 만들고 위 GitHub 저장소를 연결합니다. 쓰던 프로젝트의 환경변수나 설정을 복사했다고 가정하지 마세요.
2. 필요한 환경변수의 **이름**을 위 목록과 대조하고, 실제 값은 Vercel의 비밀 입력란에만 넣습니다. 화면을 캡처할 때 값은 가리세요.
3. 저장소의 `vercel.json`에 적힌 빌드 명령과 공개 폴더를 확인하고 배포합니다. 시작 틀은 Vercel이 제공하는 저장소·커밋·배포 URL 정보가 없으면 일반 `npm run build`가 실패합니다.
4. 배포가 완료되면 새 주소로 첫 화면을 엽니다. 실제 기능과 로그인·거절 동작도 별도로 확인합니다.
5. 환경변수 이름을 넣는 화면, 배포 완료 화면, 첫 화면을 `package/self-check/P7-1.png`부터 `P7-3.png`까지 캡처하고 `SELF-CHECK.md`에 결과를 적습니다.
